# 稳定维护与科研探索

Workflow Monitor 将行为明确的稳定维护与存在不确定性的科研探索分开。

## 稳定维护

文档、已知缺陷修复、常规重构和行为明确的改动使用 `stable` 轨道并留在 `main`。任务记录目标、验收条件、进展、证据、最终判决和交接。

## 科研与实验

新理论、算法、架构或不确定行为使用 `research`、`experiment` 或 `sandbox`，并指定主题。每次探索包含分支、假设、证据、结论和处置状态。验证通过后可以准备 Squash PR，但合并必须等待用户明确批准。

## 典型生命周期

1. 读取动态上下文和相关仓库规范。
2. 以范围和验收条件开始任务。
3. 在正确的稳定或探索轨道工作。
4. 更新结构化进度；新证据改变判断时，在研究篇章内追加修订记录。
5. 运行规定测试和完整性检查。
6. 以证据、判决和准确下一步结束任务。

程序崩溃不代表可以删除状态。应使用恢复命令继续，或在说明原因后明确放弃任务。

## 研究篇章、灵感与资料

大目标通过非线性的研究篇章组织。一个篇章可以反复推进、包含多轮探索、暂停后让另一篇章插入，并在之后恢复。`paused` 明确区分“暂时中断”和“暂时收束”；暂时收束仍可重启，只有 `completed` 才永久封存。新证据推翻旧判断时，修订记录以追加事件保存原因、最新篇章概况和证据，它属于篇章内部的判断演化，不是独立决策系统。

科研资料进入 `resources/` 的标准子目录并通过 catalog 登记；`resources/sparks/` 保存自由 Markdown 灵感，登记是可选的。`check` 验证已登记文件和索引一致，但不会因未登记灵感失败。
